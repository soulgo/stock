# ADR-001: 目录分层——入口 / 指标库 / 离线工具 / 数据 / 报告 / 资料

## Status
Accepted（2026-11-18）

## Context

系统从 2026-11-05 的单脚本长成 12 个 `.py`、27 个 `data/` 文件、50 个 `reports/` 文件、8 份 Markdown。所有东西都在根目录平铺，具体症状：

1. **三个层级混在同一平面**：入口脚本（被定时任务按名调用）、指标库（被入口 `import`）、一次性工具（偶尔手动跑）并列，无法从目录判断"改这个会不会影响当天报告"。
2. **产物写在代码旁边**：`sweep_result.json`(118K)、`grid_plan.json`、`grid_data.json`、`broad_snapshot.json` 在根目录，与既有 `data/` 约定冲突。
3. **文档名与内容错位**：`readme.md` 实际是 771 行 KDAS 手册，项目没有入口说明；新人打开 readme 想看"怎么跑"，得到的是宏观理论。
4. **报告目录不可判定性**：50 个文件里 5 类混放、3 套命名（`_noon_x.preview.txt` 与 `_noon_x_preview.txt` 并存），无法判断哪份是当日最终版。
5. **重复实现**：`secid()` 4 份、UA 常量 5 份；`kdas.py` 与 `brief.py` 各有一套 KDAS 实现（双真源）。

## Decision

按**「读写主体 × 访问频率」**分四层，不按文件类型分：

| 层 | 判据 | 位置 |
|---|---|---|
| 入口 | 被定时任务 prompt 按文件名调用 | 根目录，**名字锁死** |
| 指标库 | 被入口 `import`，一个 K0x 一个模块 | `indicators/` |
| 离线工具 | 不在日链上，失败不影响当天报告 | `tools/` |
| 产物 | 脚本读写、人不需要打开 | `data/`、`reports/archive/` |
| 资料 | 只读、追溯用 | `docs/` |

**路径唯一真源**：新增 `paths.py`（`ROOT` / `DATA` / `REPORTS` / `ARCHIVE`），迁移的脚本一律显式算 `ROOT`，禁止依赖 cwd。

## Consequences

**变容易的**

- 改了 `tools/` 里的任何东西，可以确信不影响当天的三份报告。
- 新增一个指标有固定落点（`indicators/` + `knowledge/K0x.md` + `brief.py` 的 `BLOCKS` 一行）。
- 报告目录只剩当日产物，"哪份是最终版"不再是问题。
- 打开 `readme.md` 得到的是导航，不再是 43KB 理论。

**变困难的 / 代价**

- **入口脚本名从此是接口**。`brief.py` / `report_gen.py` / `evening_gen.py` / `mx_snapshot.py` / `etf_flow.py` 一旦改名，4 份定时任务 prompt 全部失效，其中云端 2 份只能读不能改。这条约束必须写进任何后续方案。
- `indicators/` 的两个模块要 `sys.path` 引导才能 `from paths import ROOT`，比根目录平铺多两行样板代码。
- 旧命令 `python sweep.py` 变为 `python tools/sweep.py`，历史文档与记忆里的命令需要同步更新（无兼容壳，失败是响亮的"文件不存在"，不会静默出错）。

## Alternatives considered

| 方案 | 放弃原因 |
|---|---|
| **全部平铺，只整理 data/reports** | 解决了"找不到产物"，但 P1/P6/P7 全保留，根目录仍是 12 个 `.py` 的平面 |
| **做成 `src/` 包 + `python -m` 调用** | 4 份 prompt 按 `python brief.py morning` 写死，改造需同步云端（读不到、改不了），收益不抵风险 |
| **`data/` 内部再分 snapshots/cache/series** | `data/_mx_<date>.json` 与 `data/etf_flow.csv` 被 prompt 硬编码，其余 20 个文件分层的收益小于"漏改一个路径常量"的风险。等文件数破 50 再议 |
| **给旧路径留兼容壳（stub）** | 5 个入口脚本名未改，无需壳；tools 报错足够响亮，加壳反而掩盖 |

## 明确不在本 ADR 范围内

- **拆分 `brief.py`（2106 行）与 `report_gen.py`（1803 行）**：涉及 print 文本契约改造，属行为变更，需独立 ADR。
- **把 `brief.py` 输出从"人读文本"改成 JSON**：这是当前最大的架构债（改一边不会报错，只会静默丢数据），但改造面覆盖 12 个 parser + 全部渲染器，风险与工作量都不是一次目录整理该承担的。
