# ADR-003: 面板契约集中到 panel.py，渲染层改读 JSON 快照

## Status
Accepted（2026-11-18）

## Context

`brief.py` 打印一份面板文本，`report_gen.py` / `evening_gen.py` 用正则把它读回来渲染 HTML。
这条链路的所有问题都来自「契约没有单一实现处」：

- 解析代码分散在两个渲染器里：`report_gen` 16 个 `parse_*`、`evening_gen` 5 个，后者还 `import` 前者的解析器；
- 格式漂移没有任何机器约束（HANDOFF 坑 #3 / #4 / #5 同一病根）；
- 渲染器与「打印格式」硬耦合：改一句 `print` 就可能让某段消失，而且不报错。

## Decision

**把解析集中到一个中性模块 `panel.py`，并让渲染器改吃结构化快照。**

1. `panel.py` 持有全部解析器（21 个函数）+ `num/yuan/short_name/sec_title` 四个格式化基元；
   `report_gen` / `evening_gen` 通过 re-export 使用，外部调用一行不改。
2. `brief.py` 每次运行完，用**同一批解析器**把刚打印的文本转成 dict，落 `reports/_panel_<mode>_<date>.json`。
3. 渲染器 `read_panel()` 优先读快照；读不到或校验不过就回落文本解析（行为与今天一致）。
4. 快照带**文本指纹**（换行归一后 sha256 前 16 位）。只有快照确实由这份文本解析而来才采用——
   否则补跑历史日期时会静默用错数据。mtime 判据在这种场景下不可靠，所以不用。
5. `panel.validate(d, mode)` 做字段级校验：必备段缺失只告警（stderr），不中断报告。
   理由是宁可交一份缺段的报告，也不能让 08:30 的定时任务整个挂掉。

## 为什么不是「数据层定义结构」（brief 直接产 dict，渲染器只读 dict）

这是本次评估后**主动放弃**的方案，理由有两条硬约束：

1. **面板文本不可能消失**。4 份定时任务 prompt 要求 agent 读 `reports/_<mode>_<date>.txt` 里的
   数字来写决策 JSON。文本是**第一消费者的输入**，不是「可选的渲染目标」。所以「渲染器改读 dict」
   之后文本仍要产出，产物数量不减反增，两条序列化必须同时维护。
2. **字段口径是文本形状的**。`parse_*` 的输出里有大量字符串字段（`price: "3.955"`、
   `space: "3.4%"`、`k01.chg: "，较上一记录 +60.19亿份"`、`main_s: "+509万"`）。
   要让 brief 直接产这个形状，等于把 21 个解析器的字段语义在 `brief.py` 里重写一遍（约 400 行），
   而收益只是「省掉一次解析」。以本项目单消费者、6 个指标的规模，这是负收益。

代价要写清楚：**文本仍是事实来源**。如果打印格式改了而解析器没跟上，`panel.validate` 只能发现
「段缺失/变空」，发现不了「数值串到了别的字段」。这是本方案相对「数据层定义结构」的已知短板，
接受它，因为换成硬契约要付出的重写量不成比例。

## Consequences

**变容易的**

- 解析只有一份实现：改格式时，`print` 与解析器在同一次提交里对照着改，不会漏掉第二个渲染器。
- 渲染器不再含正则，`report_gen.py` 从 1803 行降到 1325 行，`panel.py` 成为唯一「格式知识」所在地。
- 快照让「同一份数据」可以被反复渲染、被第二个消费者读（微信推送/看板），不用再写第三份解析。
- 契约体检有了量化口径：`tools/panel_check.py` 会把历史面板逐份跑 `validate`，缺项率一目了然。

**变困难的 / 代价**

- 多一个产物 `_panel_<mode>_<date>.json`；它必须与 txt 同批产生，否则按文本解析（有指纹把关，不会错用）。
- `brief.py` 改成「先捕获 stdout、再统一输出」，异常路径要保证已产出的面板仍然吐出去（已在 `finally` 里处理）。
- 已知短板：数值错位类漂移发现不了（见上）。

## 怎么验证（已固化进 `tools/panel_check.py`）

1. **解析等价**：`panel.py` 的 `parse_*` 与搬迁前 `report_gen` 的实现，在 15 份历史面板文本上
   产出完全相同的 dict → 已验证全一致。
2. **双路径等价**：同一次运行的数据，走快照与走文本各渲染一次，HTML **字节级一致** → 早盘/晚报均验证。
3. **基线回归**：用 11-18 09:07 的原始面板重渲染早盘、11-17 午盘、11-18 晚报，与重构前 HTML
   字节级比对 → 三份全 0 差异。
4. **指纹两条分支**：指纹匹配走 json、改一个字符回落 text → 均验证。
